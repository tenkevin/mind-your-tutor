# QA criteria: C2 · Data checks engine

Done when: the data checks from `project/curriculum.js` are ported to `packages/domain`, with a test for each check, including the deliberate errors in `fixtures/water-cycle`.
Sources: `issues()` in `project/curriculum.js`, `docs/spec/curriculum-pack.fields.json` ("missing" behaviour), `docs/ARCHITECTURE.md` §7 (errors block publishing; warnings and info don't), Teacher Settings "Data checks" and "Ask Atlas" in `project/Teacher Settings.dc.html`, `fixtures/water-cycle/README.md`.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C2-F1 | must | Prototype checks are ported | Run the checks on packs that trigger each one in `issues()` | Missing media → info; missing standards codes → warning; unknown `requires` id → error; prerequisite loop → error. Same levels as the prototype |
| C2-F2 | must | The sample gives exactly the documented problems | Run the checks on the parsed `fixtures/water-cycle` pack | Exactly: 1 error (`ground` requires unknown `aquifer`), 1 warning (`rain` has no codes), 1 info (11 ideas without media). Nothing else |
| C2-F3 | must | Cross-row checks from the spec | Build packs with: a duplicate `idea_id`; a link whose `from_id` or `to_id` is unknown; an idea whose `category` isn't in Categories; an idea whose `unit` isn't in Units; an assessment row whose `idea_id` is unknown; an idea with no links at all | Duplicate id → error; unknown link end → warning, row skipped; unknown category → warning, uses the first category; unknown unit → error; unknown assessment idea → warning, row skipped; no links → warning ("can only unlock through prerequisites", explaining why it may never unlock) |
| C2-F4 | must | Loops of every shape are found | `a → a`; `a → b → a`; a 50-idea chain closing on itself; two separate loops | Each reported as an error that **lists the ideas in the loop**. Two loops give two issues |
| C2-F5 | must | Knock-on blocks are found | An idea that requires another idea which itself has an unknown id or sits in a loop (an indirect problem, not the idea carrying the error) | Reported as a warning ("may never unlock") that names the idea and the upstream cause. The idea that carries the direct error gets only the error, not this warning as well |
| C2-F6 | must | Coverage checks for assessment | A unit with fewer Assessment rows than ideas | Info: "Unit n: k of m questions; Atlas can draft the rest" (matches Teacher Settings → Assessment questions) |
| C2-F7 | must | Each issue has a stable shape | Inspect the output type | `{ kind, level: error \| warning \| info, message, items: ideaIds[], fix: { tab, column } }`. `kind` values are stable strings that the UI and Atlas can rely on. The type comes from `@ideamap/contracts` |
| C2-F8 | must | Blocking is computable | Call the helper on the sample and on a clean pack | `canPublish` is false for the sample (1 error) and true for the clean pack |
| C2-F9 | must | Tests | Read the test file | At least one test per `kind`, plus the fixture test C2-F2 |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C2-S1 | must | Messages are data, not markup | Ideas titled `<img src=x onerror=alert(1)>` and `{{constructor}}` | Messages carry the raw text. No HTML is built in the domain layer, so escaping is the UI's job |
| C2-S2 | must | Deep or hostile graphs can't crash it | A 10,000-idea `requires` chain; one idea requiring 5,000 others | Finishes without a stack overflow (iterative traversal or a depth guard) |
| C2-S3 | must | Domain purity | Inspect imports | No network, file or database access in the checks |

## Performance

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C2-P1 | must | Sample is instant | Time 100 runs on the sample | Median under 5 ms |
| C2-P2 | must | Large packs scale | 2,000 ideas, 6,000 links, 2,000 assessment rows, with 20 seeded problems | Under 200 ms, finding all 20 |

## Usability (teachers read these in Teacher Settings; Atlas uses them)

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C2-U1 | must | Messages say what's wrong and where to fix it | Read every message from C2-F1 to C2-F6 | Plain English; names the idea titles (not just ids); says which tab and column to change, e.g. "Groundwater requires "aquifer", which isn't an idea_id in the Ideas tab. Fix it in Ideas → requires." |
| C2-U2 | must | Messages match the prototype's wording where one exists | Compare with `issues()` in `curriculum.js` | Same meaning, no weaker warnings |
| C2-U3 | should | Summary line | Call the summary helper on the sample | "3 to review" (as in Teacher Settings "Data checks · …") |
