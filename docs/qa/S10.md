# QA criteria: S10 · Student map preview: draw and click the published map

Done when: a student signed in to the student app sees the map of their class's pinned published version, drawn as in Idea Map Explorer v2, and can click (or press Enter on) an idea to open a read-only idea page. Lock state comes from the server at zero progress. A teacher using "Preview as student" can open every idea. No tracker events are sent yet; S2 adds the events and live progress on top of this task.
Sources: `docs/ARCHITECTURE.md` D2 (pinned version), D9 and D12 (explanations: sheet text, or an AI draft only after teacher approval), D17 (UDL), D43 (`key_terms`; scope arrives with C16), D44; §8.4 (never show a locked idea as open); `project/Idea Map Explorer v2.dc.html` (visual reference); `project/_ds/` and `packages/ui` (Nocturne tokens); S5 components (`apps/student/src/udl/`); C3 derived output (`layout`, `ranked_links`); C5 (pinned version); F5 (route policies); `docs/qa/README.md` (UDL 3.0 checklist).

Boundary:
- In scope: one read API for a class's map, and the student app's map and idea page. Match the prototype's visuals, not its structure (AGENTS.md).
- Out of scope: tracker events and live progress (S2), M4's stored map views, exercises and practice (S6), chat (S4), scope filtering (C16 changes which ideas the derived `layout` holds), and remediation zoom (S9).

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| S10-F1 | must | Pinned version only (D2) | Class pinned to version 1 while version 2 is a draft, then pin version 3 | The map shows the pinned version only, never draft content; after re-pinning, a reload shows the new version |
| S10-F2 | must | No published map yet | A class with no pinned version | A plain message: "Your teacher hasn't published this map yet." No error, no empty canvas |
| S10-F3 | must | Draws the stored layout | Load the map for the sample fixture and for a pack with C12 or C16 data | Positions come from the version's derived `layout` (centre, rings, x and y), and links from `ranked_links.kept`. Nothing is laid out again in the browser. Hidden links are not drawn |
| S10-F4 | must | Matches the design | Compare with Idea Map Explorer v2 | Same ring arrangement, idea cards, category colours and icons, link arrows and locked and unlocked states, using Nocturne tokens from `packages/ui` |
| S10-F5 | must | Lock state from the server | Open the map as a student with no activity | The API returns each idea's state. With no progress, an idea with no `requires` is open and the rest are locked, with "Unlocks after …" naming the prerequisites. The rule runs on the server in `packages/domain` or `packages/tracker` (deterministic, unit-tested). The browser never computes it. A locked idea can't be opened by click, keyboard or URL (§8.4) |
| S10-F6 | must | Idea page | Click an open idea, or focus it and press Enter | A read-only page shows the title, category, unit, objective, the explanation (sheet text, or an A6 draft only once a teacher approved it; otherwise "Your teacher is preparing this explanation"), key terms when present, links in and out by idea name and relation, and a media placeholder card (video comes with X2 in v0.4). Back returns to the map with the same view |
| S10-F7 | must | Preview as student | Teacher clicks "Preview as student" in the teacher console | The student app opens the class's map in preview mode for the class's teacher or an org admin. Every idea can be opened. A visible banner says "Preview: students see locked ideas until they unlock them". Nothing is recorded |
| S10-F8 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build and plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |
| S10-F9 | must | Runs in the local demo | `pnpm dev:auth`, both apps, sign in as `student-a1` after publishing a version to Science 6A | The map draws and ideas open. The PR includes screenshots of the map, an idea page and the preview banner |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| S10-S1 | must | Scope (F5) | A student requests another class's map, a student from another org, and a signed-out request | 403, 403 and 401. The new route declares a policy and is in the policy sweep |
| S10-S2 | must | Preview is staff-only | A student tries preview mode via URL or parameter | Refused; the student sees their normal map |
| S10-S3 | must | No teacher-only data | Inspect the API response as a student | No `notes`, no unapproved drafts, no data-check issues, no other students' data |
| S10-S4 | must | No events yet | Use the map and pages | No tracker events and no analytics calls are sent |
