# QA criteria: L1 · Pilot: one curriculum shared by two classes

Done when: two pilot classes share one curriculum through import, publish, a student run and teach-back.
Sources: all of `docs/ARCHITECTURE.md` (D1–D29); every merged task's criteria; `fixtures/water-cycle/`; CXB items marked for L1 or deployment.

## Functional (end to end, on a staging deployment)

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| L1-F1 | must | Import to publish | An author imports water-cycle.xlsx, fixes the planted error, re-imports and publishes to classes 6A and 6B | The draft has 1 error, 1 warning and 1 info, then publishes after the fix; both classes are pinned to the same version |
| L1-F2 | must | Class settings stay separate | Teacher A sets due dates and a persona override; teacher B doesn't | Only 6A changes |
| L1-F3 | must | Student run | A 6A student signs in, opens ideas, takes quizzes, masters a unit and teaches back to Milo | Mastery, XP, streak and cards follow §8.3; the teacher sees the timeline |
| L1-F4 | must | Feedback loop (D15) | The student challenges feedback; the teacher rules on it | The ruling reaches the student and becomes a labelled example |
| L1-F5 | must | Privacy end to end | FERPA-export, then delete the pilot student | Every table in F6's inventory is covered |
| L1-F6 | must | Fairness monitoring (D16) | Run M6 on the pilot data | Runs, with small groups suppressed |
| L1-F7 | must | Manual checks from CXB | Real Excel and Google Sheets open the exports; the retention job runs on a schedule; backups expire | Each done and recorded |
| L1-F8 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build, plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |
