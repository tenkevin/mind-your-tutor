# QA criteria: C14 · Idea scope and key terms in the pack

Done when: per D43, Ideas carry `scope` (prerequisite, core, extension) and `key_terms`, and Units and Ideas carry `oer_reference`. Both are in `docs/spec/`, zod contracts, C1 import from CSV, XLSX and pack JSON, C2 data checks, C5 diff and C6 export. A pack without the columns behaves exactly as before.
Sources: `docs/ARCHITECTURE.md` D43, D41 (`layer` is a separate column), D8, D12; `docs/decisions/2026-10-29-water-cycle-pilot-graph.md`; `docs/spec/`; C1, C2, C2cx5, C5, C5cx1, C6, C6cx1, C6cx2, C10, C12; `fixtures/water-cycle/`.

Boundary: pack data, checks, diff and export only. Laying out each scope is C16. Zoom and sandbox views are S9. The pilot pack is C17.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C14-F1 | must | Spec and contracts | Read `docs/spec/` (README, fields JSON, schema) and parse Ideas rows | Ideas gain `scope` ∈ prerequisite, core, extension (`sheet`; missing means core) and `key_terms` (list, comma-separated in CSV and XLSX, an array in JSON; `sheet`; missing means none). Each has a type, missing behaviour, note and example. The note on `scope` says it is independent of `layer`, and `unit` stays required for every scope |
| C14-F1b | must | OER reference | Parse Units and Ideas rows | Both gain `oer_reference` (text, `sheet`, optional; for example "OpenSciEd 6.3, lesson 4"). Its note says that reused OER text or figures need the attribution kept in Library provenance (C15). The diff and export carry it like the other columns |
| C14-F2 | must | Three forms agree | Add both columns to the water-cycle fixture as CSV, XLSX and pack JSON (at least one idea in each scope, several with key terms) and import all three | The parsed packs are deep-equal. Earlier tabs and documented deliberate errors are unchanged, and the fixture README lists the new values |
| C14-F3 | must | Backward compatible | Import the current fixture and a Kinematics-style pack without the columns | Every idea is core with no key terms. Derived output (ranking, layout, quizzes) is byte-identical to before the change |
| C14-F4 | must | Data checks | Import: an invalid `scope` value; a pack with no core idea; a core idea whose `requires` names an extension idea; the same key term repeated within one idea; a key term equal to an idea title | Invalid scope and no core idea are **errors** that block publishing, located by tab, row and column. Core requiring extension is a **warning** ("extension ideas build on the core, not the other way round"). A duplicate term is **info**. A key term matching an idea title is a **warning** ("this term is also an idea; link to the idea instead"). Each message names the ideas |
| C14-F5 | must | Diff (C5) | Publish, then change one idea's scope and add and remove key terms | The diff lists scope changes (old → new) and key-term additions and removals by idea display name, independent of order |
| C14-F6 | must | Export (C6) | Export to CSV, XLSX and pack JSON and re-import | Round-trips, with canonical line endings (C6cx2) |
| C14-F7 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build and plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |
