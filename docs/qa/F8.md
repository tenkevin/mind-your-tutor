# QA criteria: F8 · Theme contract: semantic tokens and swappable themes

Done when: per D46, every colour (and every font, radius and shadow that a theme may change) reaches the apps only through named CSS custom properties defined by a **theme**. Nocturne is the default theme. A second theme can be substituted at runtime, without code changes, by adding one theme file. Map, category and state colours (open, locked, mastered, link, focus) are tokens too.
Sources: `docs/ARCHITECTURE.md` D46, D10 (Nocturne unchanged; its 9 accepted contrast exceptions apply to Nocturne only), D17 (UDL; WCAG 2.1 AA); `packages/ui` (`tokens.ts`, `styles.css`, `styles.test.ts`, README); `project/_ds/`; `project/Idea Map Explorer v2.dc.html` (map, category and state colours); S10 (first consumer); S14 (v0.3 cosmetic themes, which will use this contract).

Boundary:
- In scope: the token contract, theme files, the switch mechanism, checks, and moving S10's map colours onto tokens if S10 has merged.
- Out of scope: choosing or unlocking themes (S14, v0.3), any new visual design, and persisting a student's choice.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| F8-F1 | must | Theme contract | Read `packages/ui` | One typed contract lists every themeable token. Semantic names cover surfaces, text, accent, divider, focus, the map (`--map-node-open`, `--map-node-locked`, `--map-node-mastered`, `--map-link`, `--map-centre` or equivalents), a category palette (at least 6 slots, assigned by category order, not hard-coded names) and feedback states (success, warning, danger, info). Nocturne's existing tokens keep their names and values (D10) |
| F8-F2 | must | Themes are files | Read `packages/ui/src/themes/` | Nocturne is `nocturne.ts`, a complete value set for the contract. A theme is applied as `[data-theme="<id>"]` custom properties on the root, generated from the theme file. The default with no attribute is Nocturne, so nothing changes visually today |
| F8-F3 | must | Substitution works | Add a test-only theme with obviously different values, switch to it at runtime in a test page and in a component test | Every themed element changes without a reload or code change. Switching back restores Nocturne exactly |
| F8-F4 | must | Contract is complete | Type-check a theme missing one token; build | A missing token is a type error; an extra unknown token is an error. `styles.test.ts` (or a new test) fails if the stylesheet and the contract drift apart |
| F8-F5 | must | No raw colours outside themes | Run the new check over `packages/ui/styles.css` (outside theme blocks), `apps/*/src` (CSS, TSX, TS) and inline styles | No hex, rgb(a), hsl(a) or named colours outside theme files. The one existing `rgb(117,117,117)` in `styles.css` becomes a token. The check runs in CI (a lint rule or a test) and names the file and line |
| F8-F6 | must | Contrast per theme | Run the contrast test for every theme | Every text pair meets 4.5:1 and every UI-component pair 3:1 (WCAG 2.1 AA) on both grounds. D10's 9 named exceptions are allowed **only** for Nocturne; any other theme must pass outright |
| F8-F7 | must | Docs | Read `packages/ui/README.md` | Explains the contract, how to add a theme (one file plus registration), the contrast rule and the no-raw-colours check |
| F8-F8 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build and plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |

## Security

| F8-S1 | must | No runtime injection | Try to set a theme id that isn't registered, or a value containing `;}` | Unknown ids fall back to Nocturne; values come only from typed theme files, never from user input or the network |
