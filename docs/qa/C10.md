# QA criteria: C10 · Practice tab: spec, contracts, import, checks, diff and export

Done when: per D40 and D8, the ninth Curriculum Pack tab, Practice, is defined in `docs/spec/`, validated by zod contracts, imported from CSV, XLSX and pack JSON (C1), checked (C2), diffed (C5) and exported (C6), with every row's vetted source and licence.
Sources: `docs/ARCHITECTURE.md` D8 (nine tabs), D40 (vetted item banks only; `source_bank_id`, `license_type`, `attribution_string`), D41 (standards), D4, §7; `docs/decisions/2026-10-29-prototype-spec.md` §5; the Practice tab in `project/curriculum-pack.js` (columns, missing behaviour, example row) and `project/Curriculum Pack.dc.html`; C1, C2, C2cx5, C5, C6, C6cx1, C6cx2 (canonical line endings); `fixtures/water-cycle/`.

Boundary: data in and out only. Showing exercises to students is S6; exercise levels and trace-back are M8; the kinematics fixture is C11.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C10-F1 | must | Spec | Read `docs/spec/` (README, fields JSON, schema) | Practice is the ninth tab with every column from `project/curriculum-pack.js` plus `source_bank_id`, `license_type` and `attribution_string`: type, required, `sheet`/`app`/`both`, missing behaviour and an example, matching the prototype's wording; one row per problem, rows sharing `exercise_id` form one exercise; `demo_video_url` and `demo_steps` are read from an exercise's first row |
| C10-F2 | must | Contracts | Parse valid and invalid Practice rows with the F3 schemas | `kind` ∈ exercise, quiz; `problem_type` ∈ mc, number; `choices` and `demo_steps` are pipe-separated lists; `quiz_from` lists exercise ids; `visual` accepts `graph: x,y; …` and `table: …` and rejects other forms; a pack without a Practice tab still parses (empty list) |
| C10-F3 | must | Three forms agree | Add a Practice tab (at least 3 exercises, one quiz, mc and number problems, one graph visual) to the water-cycle fixture as CSV, XLSX and pack JSON, and import all three | Deep-equal parsed packs; earlier tabs unchanged; the fixture README lists the new rows and any deliberate errors |
| C10-F4 | must | Vetted sources only (D40) | Import rows with an allow-listed `source_bank_id` and `license_type`, an unknown bank, an unknown licence, and a CC-BY row with no `attribution_string` | Allow-listed rows pass. The other three are data-check **errors** that block publishing (C2cx5), each located by tab, row and column. The allow-list is configuration (OpenStax, PhET, NASA, NOAA and the licences Public Domain, CC-BY-4.0 to start), not code; tests use a test-only `fixture` bank that production configuration does not contain |
| C10-F5 | must | Other checks | Rows with: unknown `idea_id`; mc without `choices`; number problem whose `answer` isn't numeric; `quiz_from` naming a missing exercise or another quiz; two different `standard_code`s in one `group`; an empty `question` | Each is reported with the behaviour the spec gives (row skipped, warning or error), located, and listed in the stored issues; nothing generates a replacement question (D40) |
| C10-F6 | must | Diff (C5) | Publish, then change one problem's answer, add an exercise and remove one | The diff lists the changed, added and removed Practice items by `exercise_id` and problem, order-independently, like C5cx1 does for assessment |
| C10-F7 | must | Export (C6) | Export the pack and the blank template as CSV and XLSX | Practice is included with its header help; C1 reimports the export equal to the source; formula prefixes neutralised; line endings follow C6cx2; the template's example row matches the spec |
| C10-F8 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build, plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |
