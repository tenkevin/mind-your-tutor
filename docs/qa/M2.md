# QA criteria: M2 · Event ingest API and append-only event store

Done when: POST /events validates against M1, sets seq and level, drops duplicate ids, rejects unpinned versions and non-catalogue types, and writes partitioned rows. Typed text goes to InteractionText, anonymised (D26). The client batches with an offline queue. D22 retention and D24 opt-out are honoured.
Sources: `docs/ARCHITECTURE.md` D19, D22, D24, D26, §8.2, §8.5; F4 `interaction_event` / `interaction_event_key` (F4b, F4cx1); F5 policies; F6 inventory, export and delete.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| M2-F1 | must | Batch ingest | POST 50 valid mixed events as a student | 200; each stored once with a server seq continuing per student and the level from M1 |
| M2-F2 | must | Idempotent | Resend the same batch, then a batch mixing new and old ids | Old ids are dropped without error; new ones get the next seqs; no gaps for accepted events |
| M2-F3 | must | Rejections | Send an unknown type, a forbidden field, a version the class isn't pinned to, and a version from just before a publish (inside and outside the grace period) | Rejected with a per-event reason, except the in-grace one, which is accepted; valid events in the same batch are still stored |
| M2-F4 | must | Typed text | Send teachback.done with text naming a classmate | The text is stored in `InteractionText` with names already labelled (from the client, D26); the server backstop counts a privacy miss if a real roster name arrives, blurs it and never stores it raw |
| M2-F5 | must | Client queue | Go offline, generate events, come back | Events are queued (storage scoped to the signed-in user), sent in order, and not duplicated |
| M2-F6 | must | Opt-out (D24) | Opt a student out, then ingest | Events are still stored (the app needs mastery) and carry an opt-out mark that audits and research exclude |
| M2-F7 | must | Retention (D22) | Unenrol a student from the district; run a FERPA delete on another | Their events and text are deleted by F6's jobs; partitions, other students and aggregates are unaffected |
| M2-F8 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build, plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| M2-S1 | must | Who can post | Post as signed out, as a teacher, as a student for another student's id or another class | 401 / 403 / 403: a student posts only for themselves in classes they're enrolled in. The route declares an F5 policy and is in the every-route sweep |
| M2-S2 | must | Append-only | As the app role, try UPDATE and DELETE on events | Refused (F4) |
| M2-S3 | must | Shadowing | Repeat the F4cx1 temp-table probes against the ingest path | Duplicates are still rejected |
| M2-S4 | must | Nothing extra recorded (D19) | Inspect stored rows and logs during ingest | No IP address, user agent or device stored or logged with events |
