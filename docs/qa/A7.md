# QA criteria: A7 · Anonymous layer: on-device entity blur and server backstop

Done when: per D26 and D27, student text is blurred on the device into neutral labels before it leaves, the mapping stays on the device and replies are re-filled; interests stay specific; a server backstop blurs anything that slipped through, counts a privacy miss and never stores raw text.
Sources: `docs/ARCHITECTURE.md` D26, D27, §9 "Privacy layer, memory and feedback", §10 (AI vendors), §12 question 12; A1 gateway; F6 inventory. Reference: the SoulSpeak paper, which the user will share. If it arrives, the coordinator adds paper-specific checks before claiming. Fixtures: synthetic K-12 sentences only.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| A7-F1 | must | Entities blurred on the device | Type 50 synthetic sentences with names (including nicknames, misspellings and lower case), places, emails, phone numbers, street addresses and school names | Everything leaving the device (network capture) has them replaced by neutral labels (Person A, Place B, …); at least 95% recall on the set, with misses listed |
| A7-F10 | must | ML NER on the device (D33, added 2026-10-28) | Inspect the device layer; run A7-F1's set | Names and places come from an on-device ML NER model behind `EntityRecognizer`, not given-name or place word lists; pattern rules remain for contacts and school identifiers; CI runs without a network download (bundled model or a test double, plus one test against the real model) |
| A7-F11 | must | Fails closed without a model (D33, added 2026-10-28) | Block the model file (offline, blocked URL, no Cache API); then configure an alternative model and block only the first | With no loadable model, student chat is blocked with a calm, plain message and nothing is sent; the device never falls back to word lists. With an alternative configured, the device switches to it and chat works |
| A7-F2 | must | Interests stay specific (D27) | "I love Real Madrid and my cat Luna" | Interests reach the model unchanged; people and places are labelled |
| A7-F3 | must | Consistent labels | The same name twice, and two different names | The same entity gets the same label within a conversation; different entities get different labels |
| A7-F4 | must | Re-fill | The reply refers to Person A | The student sees the real name; the server and the model never did |
| A7-F5 | must | Server backstop | Bypass the client (send raw text with a roster name straight to the API) | The name is blurred before the model call, a privacy-miss counter goes up, and nothing raw is stored or logged |
| A7-F6 | must | Every model path | List student routes that reach a model | All go through A7 on the device and the backstop on the server; a test enumerates them |
| A7-F7 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build, plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |
| A7-F8 | should | Backstop catches lower case and outsiders (CXB, Claude QA A1 run 1) | Send "sam said hi", a name of someone outside the class, and two students who share a surname part | Lower-case and out-of-class names are blurred; a shared surname part alone doesn't blur unrelated words |
| A7-F9 | should | No raw echo to the student (CXB, Claude QA A1 run 1) | The model reply echoes a roster identifier | The student's client gets the same re-filled or blurred text the server stores, never a raw roster identifier from the model |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| A7-S1 | must | Mapping never leaves the device | Inspect network traffic, server storage and logs | The label-to-name mapping appears nowhere off the device; on the device it is cleared on sign-out |
