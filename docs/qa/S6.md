# QA criteria: S6 · Idea page and exercise player

Done when: per D40 and D42, the student's idea page shows a placeholder card for its overview video (until X2, v0.4) and the idea's vetted Practice exercises, with **Worked example** and **Mastery practice** tabs as in `project/Kinematics Explorer.dc.html`. Practice sends tracker events. Exercise levels come from the tracker (M8) and are never computed in the browser. Practice items are shown verbatim with their attribution.
Sources: `docs/ARCHITECTURE.md` D2 (pinned version), D17 (UDL), D19 and §8.2 (what is traced; **§12 q27 interim: Practice reuses the quiz events with question ids `practice/<exercise_id>`; worked-example viewing sends nothing**), D20 and D21, D38, D40 (vetted only, verbatim, attribution; D40 strict), D42 (placeholder cards, no third-party player), D46 (theme tokens), D47 (far ideas hidden), §8.4 (never show a locked idea as open); `project/Kinematics Explorer.dc.html` (exercise list, tabs, levels `Not started`, `Attempted`, `Familiar`, `Proficient`, worked-example steps); C10 (Practice tab spec in `docs/spec/`); M8 (levels); S2 (events from the explorer); S10, S10b, S10c and the merged idea-page design (#52); `docs/qa/README.md` (UDL 3.0 checklist).

Boundary:
- In scope: the Practice section of the idea page, the exercise player, the read API for an idea's exercises and levels, and the events Practice sends.
- Out of scope: video hosting and playback (X2, v0.4), level rules (M8), teacher views (M9), Ms. Ivy and Milo (S4), remediation zoom (S9), and a teacher's own uploads (D40 strict: they are never Practice).

## Functional

|---|---|---|---|---|
| S6-F1 | must | Builds on the idea page | Open an open idea with Practice rows, and one without | Everything S10-F6 and the merged idea-page layout show stays. An idea with no Practice rows says "No practice for this idea yet." No error, no empty frame |
| S6-F2 | must | Video placeholder (D42) | An idea or exercise with `media_url` or `demo_video_url` set | A placeholder card says the video is coming. Nothing is fetched from the URL, and no third-party player or iframe is loaded |

| S6-F4 | must | Mastery practice | Work an exercise with an mc problem, a number problem with `answer_unit`, and a `graph:` and a `table:` visual | Question, choices, visual and unit render as the C10 spec defines. Answers are checked as the spec defines (a number answer by value as the spec states). After each answer the row's `explanation` shows. The run ends with a score |
| S6-F5 | must | Correctness from the server | Submit a wrong answer while the client claims `correct: true`, and the reverse | The stored `quiz.answered.correct` matches the published answer key on the server, never the client's claim |
| S6-F6 | must | Events (§8.2, §12 q27) | Work one exercise to the end, then retry it | `quiz.started` (`ideaId`, a new `attemptId`, `questionIds` as `practice/<exercise_id>` ids from the pinned version), one `quiz.answered` per answer (`attemptId`, `questionId`, `choice`, `correct`, attempt number, `secondsToAnswer` as whole seconds, D19 revised) and `quiz.finished` (`score`, `of`). Each carries the pinned `versionId`. A resent event is recorded once (M2). No other event types, no free text, and nothing D19 never records |
| S6-F7 | must | One mapping point (§12 q27) | Read the code | Practice-to-event mapping lives in one place in `packages/contracts` and is read by one tracker adapter, so dedicated `exercise.*` events could replace it later without reshaping tracker state or the UI |
| S6-F8 | must | Levels from the tracker (M8) | Finish runs that should move an exercise from Not started to Attempted, Familiar and Proficient; reload | Each level comes from the API, computed by M8's rules by replaying events. | S6-F9 | must | Verbatim with attribution (D40) | Compare each shown item with its Practice row | `question`, `choices`, `answer_unit`, `explanation` and `demo_steps` match the row exactly: no AI rewording, no interest shaping (§12 q25), no generated replacement. Each exercise shows its `attribution_string`, source bank and licence visibly. Nothing other than vetted Practice rows appears in the Practice section |
| S6-F10 | must | Quiz exercises | An exercise with `kind` quiz and `quiz_from` | It draws its problems from the named exercises as the C10 spec defines, and sends the same events |
| S6-F11 | must | Locked and hidden ideas (§8.4, D47) | Request a locked idea's exercises, and a far idea's, by URL and API | A locked idea's exercises can't be opened or answered by click, keyboard, URL or API. A far idea answers like an unknown id (S10c), with no title or exercise data |
| S6-F12 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build and plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |
| S6-F13 | must | Runs in the local demo | Publish the water cycle with its Practice rows (and the kinematics fixture once C11 has merged) to Science 6A, sign in as `student-a1` | The idea page shows exercises, both tabs and levels. The PR includes screenshots of the exercise list, a worked example, a mastery run with its explanation, and the attribution |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| S6-S1 | must | Scope (F5) | Request another class's exercises, another org's, and signed-out | 403, 403 and 401. New routes declare a policy and are in the policy sweep |
| S6-S2 | must | Answers stay on the server | Inspect the API responses before a problem is answered | No answer key for unanswered problems is sent to the browser. No teacher notes, data-check issues or other students' data |
| S6-S3 | must | Only the student's own events | Send practice events naming another student, another class or an unpinned version | Refused; nothing is stored |
| S6-S4 | must | Inert content | Practice cells containing `<script>`, HTML and a `javascript:` URL | Rendered as text; URLs aren't followed or fetched |
| S6-S5 | must | Preview records nothing | Use Practice in Preview as student | No events are stored |
