# QA criteria: X2 · Self-hosted video and media provider

Done when: per D42, `media_url` and `demo_video_url` values resolve through a MediaProvider served from our own S3-compatible storage and our own domain or CDN, never third-party players, and every video has WebVTT captions.
Sources: `docs/ARCHITECTURE.md` D42 (self-hosted, own domain, VTT captions mandatory), D17 (UDL), D5, D31 (vault materials kept), §7, §10; `docs/decisions/2026-10-29-prototype-spec.md` §6; `docs/spec/` (`media_url`, and `demo_video_url` once C10 lands); C4 (object store, import job); F5 (policies); F6 (inventory).

Boundary: storing, captioning and serving media. Playing video on the idea page is S6.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| X2-F1 | must | Provider interface | Read the code | A `MediaProvider` interface resolves a pack media reference (file name or https URL) to a playable URL on our domain. The default implementation uses S3-compatible object storage (local filesystem or MinIO in tests); any other backend sits behind the same interface and domain |
| X2-F2 | must | Upload | An author uploads an MP4 (H.264/AAC) and its `.vtt` for a curriculum, then imports a pack whose `media_url` names that file | The file is stored by content, linked to the curriculum, and the published version resolves the reference; the original is kept (D31) |
| X2-F3 | must | Captions required | Upload a video without a VTT, and with an invalid VTT | Not resolvable for students; a located data-check error blocks publishing until a valid WebVTT file is attached |
| X2-F4 | must | Streaming | Request the video with HTTP Range headers | 206 partial content with correct ranges and content type, so seeking works |
| X2-F5 | must | No third parties | Load an idea's media as a student with a network log | Every media, caption and poster request goes to our own origin or CDN hostname; no YouTube, Vimeo or Cloudinary hosts |
| X2-F6 | must | External https references | A pack `media_url` pointing to a third-party https video | Not embedded; reported as a warning telling the author to upload the file (D42) |
| X2-F7 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build, plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| X2-S1 | must | Access | Fetch a media URL as a user of another org, signed out, and after the link expires | Media URLs are signed and short-lived, scoped to the org and curriculum; refused otherwise. Upload routes declare F5 policies (author or admin) and join the every-route sweep |
| X2-S2 | must | Upload safety | Upload a disguised executable, an oversized file, an HTML file named `.mp4`, and a VTT with markup and `<script>` | Screened by bytes and size; refused or neutralised; captions are served as `text/vtt` and rendered as text |
| X2-S3 | must | No student data | Read the tables, logs and inventory | Media is curriculum content; access logs hold no student names; F6's inventory lists media and captions |
