# QA criteria: T4 · Schedule: due dates per unit

Done when: due dates per unit save and appear in the API's missions feed.
Sources: `docs/ARCHITECTURE.md` §6 (due dates are class-only), §11 (Schedule: units from the published version, due dates per class), D3; `project/Teacher Settings.dc.html` (Schedule); T1 shell, T3 config layering; F5.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| T4-F1 | must | Units from the published version | Open Schedule for a class pinned to water-cycle v1 while a v2 draft exists | Lists v1's units in order; draft-only units don't appear |
| T4-F2 | must | Save per class (D3) | Set unit 1's due date in class A | Autosaves (Saving, then Saved); class B sharing the curriculum is unaffected; there is no curriculum default (§6) |
| T4-F3 | must | Missions feed | GET the class missions feed as a student of A | Units with due dates, ordered by date, with the date in the class's time zone; units without a date are listed after them as "no due date" |
| T4-F4 | must | Clear and change | Clear a date, then move one earlier | The feed updates; a cleared date removes the unit from the dated list |
| T4-F5 | must | Dates survive a publish | Publish v2 to A (C5) with a unit renamed but the same unit number | The due date stays on that unit; a removed unit's date is dropped, not reassigned |
| T4-F6 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build, plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |
