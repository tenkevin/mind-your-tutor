# QA criteria: A6 · Draft missing explanations, unit objectives and assessment questions

Done when: for each idea with no explanation, each unit with no objective and each assessment row with no question after import, Atlas or Ms. Ivy drafts one (D9, D12). Teachers review, edit and approve drafts in Teacher Settings; only approved text reaches students; approvals are stored per curriculum and survive re-import.
Sources: `docs/ARCHITECTURE.md` D9, D12, D13, §11 ("Drafts to approve"), §5 (approved_explanation); C9 (draftable warnings); A1; T2.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| A6-F1 | must | Drafts are made | Import a pack with 2 ideas lacking explanations, 1 unit lacking an objective, 1 question missing | Exactly 4 drafts, each tied to its row, made through the A1 gateway |
| A6-F2 | must | Approval gate | Before approval, open the student view or API | Students see no draft text |
| A6-F3 | must | Review | Approve one, edit then approve one, reject one | Approved and edited text is stored per curriculum and served to students; the rejected one isn't, and can be redrafted |
| A6-F4 | must | Survives re-import | Re-import the same pack, still with empty cells | Approvals persist; no new drafts for approved rows. A sheet value, once added, takes precedence (D9) |
| A6-F5 | must | Never blocks publishing (D12) | Publish with drafts pending | Allowed; pending items show as warnings |
| A6-F6 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build, plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |
