# QA criteria: A9 · Explained feedback, Challenge this and teacher review queue

Done when: per D15, formative feedback reaches the student with its reason and the rubric or key point it rests on, plus Challenge this; summative feedback waits for teacher approval or edit; challenges and rulings reach the teacher's queue; rulings are stored as labelled examples and retrieved for later feedback, never used for training; feedback events are recorded.
Sources: `docs/ARCHITECTURE.md` D15, D19 (feedback.* events), §9; A1, A2, A7; M2.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| A9-F1 | must | Formative with a reason | Answer a practice question wrongly | Feedback shows immediately with a plain reason and the key point it is based on; `feedback.shown` is recorded |
| A9-F2 | must | Challenge this | Challenge it, typed and spoken | The challenge and the AI's reasoning reach the class teacher's queue; `feedback.challenged` is recorded; the student sees "sent to your teacher" |
| A9-F3 | must | Summative needs the teacher | Submit a summative item | The student sees nothing until the teacher approves or edits; then `feedback.shown` with source teacher |
| A9-F4 | must | Rulings | The teacher upholds one challenge and overturns another | The student is told the outcome; `feedback.ruled` is recorded; an overturn corrects the student's score through a tracker event, never by editing numbers |
| A9-F5 | must | Learning loop without training | Rule on 5 challenges for one question; trigger new feedback on it | The rulings are stored as labelled examples for that curriculum and question and are retrieved into the next prompt; no request to the provider uses them for training |
| A9-F7 | must | Teacher id on teaching events (D30) | Rule, approve and edit as two different teachers | `feedback.ruled`, `teacher.feedback.approved` and `teacher.feedback.edited` each carry the acting teacher's pseudonymous id (schema updated in packages/contracts, with tests); events without it from before D30 still validate |
| A9-F8 | must | Equal weight per teacher (D30) | Teacher A gives 10 rulings on one question, teacher B gives 1 | Example retrieval weights each teacher's contributions equally (A's 10 together count the same as B's 1), shown by a deterministic test |
| A9-F6 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build, plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| A9-S1 | must | Queue scope | Another class's teacher, a student, another org | 403. Routes declare F5 policies and are in the every-route sweep |
| A9-S2 | must | Examples stay in the curriculum | Feedback for a different curriculum | Never retrieves another curriculum's or org's examples |
| A9-S3 | must | Anonymised | Inspect stored challenges and examples | A7 labels only |
| A9-S4 | must | Teacher id stays pseudonymous (D30) | Inspect events, examples, prompts and student-facing responses | Only the pseudonymous id is stored; no teacher name or email in events or prompts; students never see the teacher id |
