# QA criteria: A5 · Persona eval harness per grade band

Done when: fixed eval prompts run per grade band in CI with a pass threshold.
Sources: `docs/ARCHITECTURE.md` §9 ("An eval harness runs each persona against fixed prompts per grade band (K–2, 3–5, 6–8, 9–12) before template changes ship"), D13 (one built-in registry), A1 gateway, A2 guardrails. CI must not need a real model key: the harness runs against a recorded or mock model in CI, with a documented mode for real-model runs.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| A5-F1 | must | Coverage | List the eval set | Each built-in persona (Ms. Ivy, Milo, Atlas) has fixed prompts for each of the four grade bands; prompts are versioned files in the repo |
| A5-F2 | must | Scoring | Read the harness | Each case has explicit checks (for example reading level for the band, stays on topic, refuses personal data requests, Milo asks rather than tells), with a numeric pass threshold per persona and band |
| A5-F3 | must | Runs in CI | Open a PR that changes a built-in template | CI runs the harness; a template that breaks a guardrail case fails the build |
| A5-F4 | must | Deterministic in CI | Run the CI mode twice | Identical scores (recorded or mock responses); real-model mode is opt-in and documented |
| A5-F5 | must | Uses the real fill path | Inspect the harness | Prompts are filled by the same `packages/ai` fill used by A1, with A2 guardrails appended |
| A5-F6 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build, plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| A5-S1 | must | No secrets or student data | Inspect eval files and CI config | Synthetic prompts only; no student data; any real-model key comes from CI secrets and is never printed |
