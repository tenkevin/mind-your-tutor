# QA criteria: T1 · Teacher console shell, nav and save state

**Done when:** Teacher app shell with header, section nav and the Saving and Saved indicator, behind sign-in.

**Sources:** `docs/tasks.json` T1; `docs/ARCHITECTURE.md` §§1 (D5, D10), 4 and 11; `project/Teacher Settings.dc.html` (header and section navigation reference); cross-browser, zoom, screen-reader and chunk-name suggestions from `docs/qa/CXB.md` (Codex-F2-ui.md).

This task covers the signed-in shell and its navigation/status affordances. It does not require the later section features to be implemented. D10 remains unchanged: existing listed deviations are accepted; new text pairs must meet 4.5:1 and new UI boundaries must meet 3:1.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| T1-F1 | must | The teacher shell is available only after sign-in | In a fresh browser context with no session, open the teacher app route directly and follow any redirect. Then sign in with a seeded teacher account and open the same route. Inspect the rendered page and browser-visible response. | Before sign-in, the shell header, section navigation, save state, and teacher data are unavailable; the user is sent to the sign-in flow. After sign-in, the shell loads without another sign-in prompt. |
| T1-F2 | must | Header presents the shell identity and actions | At a desktop viewport, inspect the signed-in header against the Teacher Settings prototype and Architecture §11. | The header identifies Idea Map and the teacher surface, shows the current subject · topic, exposes the Saving/Saved status, and provides the “Preview as student” action. Items remain readable and operable without overlap. |
| T1-F3 | must | Section navigation reaches its matching section | From the signed-in shell, activate each section navigation item using a pointer, then use the browser Back/Forward controls. Check the visible section heading and URL/fragment if applicable. | Each item takes the teacher to its corresponding section in the shell; the destination is identifiable by its heading. Navigation does not require any later section feature to be implemented. |
| T1-F4 | must | Save status reflects an in-flight save and successful completion | Trigger a change through an available shell test fixture or control while delaying the save response. Observe the status before resolving the response, then resolve it successfully. If no editable control exists yet, exercise the shell with a controlled pending/success save in a focused test harness. | While the save is pending, the visible status reads “Saving…”; after successful completion it reads “Saved”. It does not report “Saved” before the response succeeds. |
| T1-F5 | must | Shell colors respect D10 | Inspect computed foreground/background pairs for shell text, section navigation, buttons, status and focus indicators on both `--color-bg` and `--color-surface`. Calculate WCAG contrast. Compare any below-threshold pairs with D10 in `docs/ARCHITECTURE.md`. | Text is at least 4.5:1 and UI boundaries/focus indicators are at least 3:1. Any below-threshold pair is already listed in D10 with the same component, state and ground; no new exception is added. |
| T1-F6 | must | Integrated checks pass | Run root lint, format check, typecheck, tests with a disposable database, build and plan check; inspect exact-head CI | All pass on the candidate containing the current base |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| T1-S1 | must | Direct navigation cannot expose the shell before authentication | Clear cookies and browser storage, request the teacher route directly, inspect the page and network responses before signing in, then sign in and retry. | No teacher shell or teacher-specific content appears before authentication; the unauthenticated route resolves to sign-in or an equivalent access-denied response. After authentication the shell is available. |
| T1-S2 | must | Teacher surface enforces role policy | Sign in as a student and attempt direct navigation plus any teacher data request; repeat with a role authorized by F5 | Student receives a safe refusal and no teacher data; authorized role can use the shell |

## Performance

No separate numeric performance gate is specified for this shell-only task. Record production build sizes for future comparison; the required root build and tests still apply. Timing/data-volume requirements belong to the later data-backed sections.

## Usability

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| T1-U1 | must | Header and section navigation work by keyboard and at 200% zoom | With a keyboard only, tab through header controls and section navigation; activate navigation with Enter/Space and use Shift+Tab in reverse. Repeat at 200% browser zoom from a 1280 CSS-pixel viewport. | Every interactive control is reachable and operable in a logical order with a visible focus indicator. At 200% zoom, header and navigation remain readable and usable, controls do not overlap or clip, and the page has no horizontal scrolling. |
| T1-U2 | should | The actual signed-in shell works in Firefox and WebKit | In current Firefox and WebKit-based Safari, sign in and repeat the header, navigation and Saving/Saved checks on the real application screen. Record browser versions and any differences from Chromium. | The header and section navigation render and operate, and both save states appear correctly in each browser. Record any mismatch; this cross-browser suggestion does not block a PASS. Source: CXB, Codex-F2-ui.md. |
| T1-U3 | should | Screen-reader users can identify and operate the shell | On the real signed-in screen, use a screen reader with a supported browser. Navigate by landmarks/headings and then through the header and section navigation; trigger a save-state change. | The screen reader identifies the page header, primary navigation and page/section heading; each interactive item has an understandable name and works; the Saving-to-Saved change is announced once. Record browser, screen reader and version. This suggestion does not block a PASS. Source: CXB, Codex-F2-ui.md. |
| T1-U4 | should | Check the name of the shared JavaScript chunk | Run the production build and inspect its emitted asset manifest/chunk names for a shared `jsx-runtime-*` chunk. Record the artifact and whether a clearer name would help reviewers or operations. | Report whether that chunk exists and give an evidence-based rename recommendation; do not require a rename where the current name is useful. This suggestion does not block a PASS. Source: CXB, Codex-F2-ui.md. |
