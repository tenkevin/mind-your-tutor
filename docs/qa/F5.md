# QA criteria: F5 · SSO sign-in, roles and org tenancy

Done when: teachers and students sign in with SSO, and every API route checks role and org.
Sources: `docs/ARCHITECTURE.md` §3, §9 and §10 (COPPA, FERPA, the sign-in providers, the roles admin, author, teacher and student, row-level security per org), D3 (one curriculum shared by many classes), D11 (class-scoped library), and the F4 schema (`docs/qa/F4.md` S1 and S2).

Note: production identity providers (Google Workspace for Education, Clever, ClassLink) need real school accounts, which open question 3 still has to settle. For QA, each provider must work against a **local mock identity provider** that runs in CI. Real provider configuration is documented but not exercised.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| F5-F1 | must | Sign-in works end to end with OIDC | Sign in through the mock provider as a teacher and as a student | A session is created, and `/me` returns the user's id, role and org. The session cookie is set |
| F5-F2 | must | Provider adapters exist for the §10 list | Inspect the auth module and its config | Google Workspace for Education and Clever (OIDC) and ClassLink (OIDC or SAML) are configured through one adapter interface. Adding a provider is configuration, not code |
| F5-F3 | must | Users are matched, not duplicated | Sign in twice with the same mock identity, then once with the same email from a different provider in the same org | One user record in the first case. In the second, a linked identity or a clear refusal, never a silent duplicate |
| F5-F4 | must | Role and org checks on every route | List every registered API route; for each, call it signed out, as a student, as a teacher of another class, as a teacher in another org, and as an admin | Signed out → 401. Wrong role or wrong org → 403. No route is unprotected except `/health` and the sign-in callbacks, and the test fails if a new route is added without a declared policy |
| F5-F5 | must | Class scoping | A teacher of class A requests class B's config, roster and library (D11) in the same org | 403, unless they also teach class B |
| F5-F6 | must | Curriculum sharing respects roles (D3) | An author edits curriculum defaults; a teacher who only uses the curriculum tries the same | The author succeeds; the teacher gets 403 (open question 1 may widen this later) |
| F5-F7 | must | Sign-out and expiry | Sign out; then replay the old cookie. Let a session pass its idle limit | Both are rejected. Idle limits: teachers 8 hours, students 2 hours (configurable) |
| F5-F8 | should | OneRoster CSV import creates enrolments | Import a OneRoster sample (users, classes, enrolments) | Users and enrolments are created in the right org, and re-importing doesn't duplicate them |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| F5-S1 | must | OIDC is done properly | Inspect the flow and try: a missing or reused `state`, a mismatched `nonce`, a token with the wrong `aud`, an expired token, a token signed with an unknown key | Each attempt is refused. Uses the authorization code flow with PKCE, never the implicit flow |
| F5-S2 | must | Cookies are locked down | Inspect `Set-Cookie` | `HttpOnly`, `Secure`, `SameSite=Lax` or stricter, host-only. No tokens in localStorage |
| F5-S3 | must | CSRF on state-changing routes | POST, PUT and DELETE from a foreign origin without the CSRF token | Refused |
| F5-S4 | must | Org isolation holds at the database too | Bypass the route layer: run an app query with org A's context against org B's ids | Zero rows (F4 row-level security), proving the API sets the org context on every request |
| F5-S5 | must | Minimal student data (COPPA) | Inspect what is stored from the identity token for a student | Only name, school email and roster ids (§10). No photo, birthday, phone or address is kept |
| F5-S6 | must | No open redirects | Sign in with `returnTo=https://evil.example` and `//evil.example` | Redirected only to same-origin paths |
| F5-S7 | must | Brute force and enumeration | 50 failed callbacks from one IP in a minute; probe `/me` with random ids | Rate-limited; errors don't reveal whether an account exists |
| F5-S8 | must | Secrets stay out of the repo | Search for client secrets and private keys | Read from environment variables only; `.env.example` lists the names with no values |
| F5-S9 | must | Audit trail | Sign in, change a role, sign out | Each writes an `AuditEvent` with actor, action, target and time (§10) |

## Performance

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| F5-P1 | must | Auth check is cheap | Time 1,000 authenticated requests to a protected no-op route | Auth overhead under 5 ms p95 |
| F5-P2 | should | Sign-in round trip | Time the mock sign-in from start to `/me` | Under 1 second locally |

## Usability

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| F5-U1 | must | Clear sign-in screen | Load the sign-in page in both apps | One button per enabled provider, using its name. No password field (SSO only). Readable at 400 px wide |
| F5-U2 | must | Helpful refusal | Sign in as a user who isn't enrolled in any class | A plain message: "Your school account isn't linked to a class yet. Ask your teacher." No raw error |
| F5-U3 | must | Expired session recovery | Let a teacher's session expire with unsaved Teacher Settings edits, then act | They're asked to sign in again and return to the same page; the autosave design means no edits are lost |
| F5-U4 | should | Developer setup | Follow the README | One command starts the mock identity provider, with seeded sample users for each role |
