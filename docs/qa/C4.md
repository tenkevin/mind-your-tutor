# QA criteria: C4 · Job queue and import job producing a draft version

Done when: uploading a file runs a pg-boss job that stores a draft CurriculumVersion with derived data and issues.
Sources: `docs/ARCHITECTURE.md` §3, §5 and §7 (the pipeline diagram, errors block publishing, versions are immutable), D2 (draft separate from publish), D8, D9, D12, the merged C1 importer, C2 checks, C3 `derive`, F4 schema, `fixtures/water-cycle`.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C4-F1 | must | Upload to draft, end to end | Upload `water-cycle.xlsx` through the API (or the job entry point in tests) and wait for the job | One new `CurriculumVersion` with status `draft`, holding the parsed pack, the C3 derived data (27 kept links, centre `evap`) and the C2 issues (1 error, 1 warning, 1 info) |
| C4-F2 | must | All three formats work | Repeat with the eight CSVs (zipped) and `pack.json` | Each gives a draft whose pack and derived data deep-equal C4-F1's |
| C4-F3 | must | Job status is visible | Poll the import job while it runs and after | `ImportJob` moves `queued → running → succeeded`, with the pipeline steps from Teacher Settings (Read sheet, Check data, Rank links, Lay out map, Make quizzes, Index library) and timestamps |
| C4-F4 | must | Blocking import errors don't create a version | Upload a file missing a required tab column | Job ends `failed` with the C1 problems attached; no version created |
| C4-F5 | must | Data-check errors still create a draft (D2) | Upload the sample (it has 1 error) | A draft is created and marked "can't publish" (C2 `canPublish` false). Publishing isn't part of C4 |
| C4-F6 | must | Versions are immutable and numbered | Import twice | Two drafts with increasing version numbers; the first is unchanged; the source file checksum and column mapping are stored on each |
| C4-F7 | must | Idempotent and retry-safe | Kill the worker mid-job, restart it; submit the same upload twice with the same idempotency key | One draft per upload; a retried job completes without duplicates |
| C4-F8 | must | Library indexing is a separate job (§7) | Inspect the job types | Import doesn't block on library indexing; indexing is enqueued separately (it may be a stub until A3) |
| C4-F9 | must | Everything passes | lint, format:check, typecheck, test, build, plan check; DB tests against Postgres in CI | All exit 0; CI green |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C4-S1 | must | Uploads are scoped and authorised | Upload as a student; as a teacher into another org's curriculum | Refused (403), using F5's route policy once merged, or the job API's own org check in tests |
| C4-S2 | must | C1 file limits are enforced before queuing | Upload a 60 MB file and a zip bomb through the API | Refused at upload with a clear message; no job queued |
| C4-S3 | must | Uploaded files are stored safely | Inspect object storage use | Stored under a random key in a per-org prefix, never under the user's file name; not publicly readable |
| C4-S4 | must | Jobs run with the right org context | Inspect the worker's database calls | Every write sets the org context (F4 RLS), so a bug can't write into another org |

## Performance

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C4-P1 | must | Sample import is quick | Time upload → draft for the sample | Under 5 seconds end to end on the CI runner |
| C4-P2 | must | Large import completes | A 2,000-idea XLSX | Under 30 seconds, with memory under 512 MB in the worker |
| C4-P3 | should | Parallel imports | Five uploads from five orgs at once | All succeed; no cross-org mixing; total under 2× a single import |

## Usability (teachers see this in Teacher Settings → Curriculum data)

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C4-U1 | must | Progress is meaningful | Read the job status during the sample import | Step names match the Teacher Settings pipeline and each step reports a short result ("18 ideas, 31 links", "3 notes", "Top 3 in and out per idea") |
| C4-U2 | must | Failures say what to do | Read the C4-F4 failure | Plain English with the C1 cell-level messages, and the next action ("Fix the sheet and upload again") |
