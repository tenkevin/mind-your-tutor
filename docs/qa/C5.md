# QA criteria: C5 · Draft vs published diff and Publish flow

Done when: the API returns a draft vs published diff, and publishing moves the pinned version for the chosen classes.
Sources: `docs/ARCHITECTURE.md` §1 (D2, D3, D12, D14), §5, §7 ("teacher reviews … Publish ──► pick classes"), `fixtures/water-cycle/`, C2/C2cx5 (`canPublish`, stored issues), C4 (drafts). Decision record: `docs/qa/codex/Codex-C5-affected-students-decision.md`.

Boundary: C5 is the API and domain logic. The Publish screen is T8. Progress migration rules are C7 (tracker); C5 must not rewrite progress or events.

Fixtures: **A** = `water-cycle` with its one data-check error fixed (remove `aquifer` from `ground.requires`), published as v1. **B** = A with: one idea added, one removed, one renamed (same `idea_id`, new name), one `requires` change, one idea moved to another unit, one assessment question edited. **E** = the unmodified sample (1 error).

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C5-F1 | must | Diff lists every §7 change kind | Import B as a draft; request its diff against published A | Exactly: 1 added, 1 removed, 1 renamed (matched by `idea_id`, not by name), 1 prerequisite change (with before/after ids), 1 unit-membership change (from/to unit), 1 assessment question change. No other entries |
| C5-F2 | must | Empty and first-publish diffs | Diff A against itself; diff a draft for a curriculum with nothing published | Identical: an empty diff, not an error. Nothing published: every idea listed as added (or an explicit "first publish" form) |
| C5-F3 | must | Diff is deterministic | Request the diff for B three times, and once after re-importing B as a new draft with rows in a different order | Byte-identical JSON in a stable order |
| C5-F4 | must | Publish moves pins for chosen classes only (D3) | Two classes share the curriculum, both pinned to A. Publish B to class 1 only | Class 1's `pinned_version_id` = B; class 2 still A; B's status is `published` with `published_at` set; A stays readable and unchanged |
| C5-F5 | must | Errors block publishing (§7, C2cx5) | Try to publish E | Refused with the blocking issues listed; no pin moves; status stays `draft`. Warnings/info alone (including D12 draftable gaps) do not block |
| C5-F6 | must | Students receiving this update (D14) | Class 1: students s1, s2, s3; class 2: s3, s4; class 3 (not selected): s5. s1 has no progress history; s2's progress won't change. Preview with classes 1 and 2, then with only 2, then with none | Counts 4 (s3 once), then 2, then 0. Students with no history or unchanged progress are counted. Unselected classes and other orgs never contribute. The count is of people, not enrollment rows |
| C5-F7 | must | Rollback = re-pin | Publish B to class 1, then re-pin class 1 to A | Allowed for an earlier **published** version; class 1 back on A; B stays published. Re-pinning to a draft or archived version is refused |
| C5-F8 | must | Publish is atomic and idempotent | Publish B to classes 1 and 2 with one class made to fail mid-way (e.g. deleted); repeat a successful publish with the same idempotency key | All-or-nothing: on failure no pin moves; the repeat is a no-op with the same result and one audit record |
| C5-F9 | must | No progress rewrite | Count `interaction_event` rows and snapshot table contents before and after publishing | Unchanged (migration is C7's tracker rule) |
| C5-F10 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL, build, plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C5-S1 | must | Who can publish | Try diff and publish as: a teacher of the class, a teacher of another class in the same org, a student, an admin of another org, no session | Only the class's teacher (or an org admin, per F5 roles) can publish; others get 403/401 and no pin moves. Cross-org ids return 404 without leaking existence |
| C5-S2 | must | Class and version must belong together | Publish org A's version to an org B class; publish curriculum X's version to a class on curriculum Y | Refused by the API and by the database guard (F4 `guard_class_pin`) |
| C5-S3 | must | Audit | Publish and rollback | Each writes an `AuditEvent` (actor, classes, from/to version) with no student names or secrets |
| C5-S4 | should | Diff leaks nothing beyond curriculum content | Inspect the diff response | No student identifiers; the count is the only student-derived value |

## Performance

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C5-P1 | must | Diff at scale | Two 2,000-idea versions differing in 10% of rows | Diff under 500 ms server-side (median of 5 warmed runs; report the cold run too) |
| C5-P2 | must | Count at scale | 30 selected classes, 3,000 enrollments with overlap | Count under 200 ms, one query (no per-student loop) |
