# QA criteria: M4 · Map generation from tracker state

Done when: generateMap reads tracker state, stores each MapView with an id, records map.shown, and never shows a locked idea as open (§8.4).
Sources: `docs/ARCHITECTURE.md` D6, §8.2 (`map.shown`, level other), §8.3 (unlocks), §8.4 rules 1–4; C3 layout; M3 state.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| M4-F1 | must | Reads tracker state only (§8.4 rule 1) | Generate for a student with 3 mastered ideas | Mastered, unlocked and locked states come from M3's state; generation keeps no progress of its own |
| M4-F2 | must | Stored with an id (rule 2) | Generate twice | Each MapView is stored with its own id, and `map.shown` points at it; replaying the tracker never calls the generator |
| M4-F3 | must | Locks respected (rule 4) | Fuzz: 1,000 generated views over random tracker states | No view shows a locked idea as open; a view that would is rejected |
| M4-F4 | must | Uses the published layout | Compare positions | The C3 layout of the class's pinned version is the base; any personalisation is stored in the view |
| M4-F5 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build, plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| M4-S1 | must | Scope | Request another student's or another class's view | 403. Routes declare F5 policies and are in the every-route sweep |
| M4-S2 | must | Determinism boundary | Inspect `packages/tracker` | Generation code lives outside the tracker; the tracker gains no randomness, clock or model calls |
