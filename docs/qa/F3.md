# QA criteria: F3 · Domain types and zod contracts for import tabs and config

Done when: zod schemas for the curriculum pack tabs, class config and versions, with tests.
Sources: `docs/spec/curriculum-pack.fields.json` (field-level spec from the Curriculum Pack design), `docs/spec/curriculum-pack.schema.json`, `fixtures/water-cycle/`, `docs/ARCHITECTURE.md` §2, §5 and §6.

Boundary: F3 checks the **shape of each row and value**. Checks that need the whole pack, such as an unknown `requires` id, prerequisite loops or a missing category, belong to C2 and must **not** fail F3 parsing.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| F3-F1 | must | One schema per pack tab, matching the spec | For each tab in `curriculum-pack.fields.json` (Course, Units, Ideas, Links, Categories, Assessment, Personas, Library), compare the zod schema's fields, required flags and types with the spec | Every column present; `req: true` columns are required; types match (integer, percent 0–100, date, list, slug, enums) |
| F3-F2 | must | Enumerations are exact | Parse rows with each allowed value and with one invalid value: `rarity`, `tone`, `persona_id`, `audience`, `use_for`, `grade` (`K` or 1–12), `importance` (1–5) | All allowed values pass; each invalid value fails |
| F3-F3 | must | The sample pack parses in every form | Parse `fixtures/water-cycle/pack.json`, then the eight CSVs and the eight XLSX sheets after list splitting (F3 may expose a row-level parse helper for this) | All three parse with no errors, to deep-equal results |
| F3-F4 | must | Spec defaults are applied | Parse rows that leave out optional columns | `importance` 3, `rarity` "auto", `tone` "warm", `audience` "Students", `use_for` "agent", `pass_mark` 70. Other optional columns come out as `null`, not `""` |
| F3-F5 | must | "Missing" behaviour from the spec is classed correctly | For each column whose spec `missing` says "Blocks import" or "Row skipped", remove it from a row | The error says whether it blocks the import or skips the row, so C1 and C4 can act on it |
| F3-F6 | must | Lists parse consistently | Parse `standard_codes`, `requires` and `key_points` from `"a, b"`, `"a;b"`, `" a ,b "`, `""` and a JSON array | Trimmed string arrays; an empty string gives `[]` |
| F3-F7 | must | Cross-row checks are not F3's job | Parse the `ground` row (requires `aquifer`) and the `rain` row (no codes) | Both parse successfully |
| F3-F8 | must | ClassConfig schema follows §6 and the spec's `edit` column | Inspect the ClassConfig schema | Has exactly the fields whose `edit` is `app` or `both` (subject, topic, grade, framework, map_objective, pass_mark, per-unit due_date, per-idea rarity, persona overrides). Every field is optional, as an override of curriculum defaults |
| F3-F9 | must | CurriculumVersion schema follows §5 | Inspect the schema and parse a sample draft and a published version | Has status `draft` / `published` / `archived`, curriculum id, the pack body, derived data, issues and a source reference |
| F3-F10 | must | Types come from the schemas | Check exports | TypeScript types are `z.infer` of the schemas and exported from `@ideamap/contracts`; no hand-written duplicates |
| F3-F11 | should | The JSON Schema stays in step | Generate JSON Schema from the zod pack schema and validate `fixtures/water-cycle/pack.json` against it | Validates. Differences from `docs/spec/curriculum-pack.schema.json` are listed in the PR |
| F3-F12 | must | Package checks pass | `pnpm --filter @ideamap/contracts build test typecheck` | All exit 0; each tab has at least one passing and one failing test case |

## Security

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| F3-S1 | must | Unknown keys can't smuggle data or pollute prototypes | Parse rows with extra keys, including `__proto__`, `constructor` and `prototype` | Unknown keys are stripped (or rejected); the output object has no such keys, and `Object.prototype` is unchanged |
| F3-S2 | must | Text fields have length limits | Parse a 1 MB string in `title`, `question` and `prompt_template` | Rejected with a clear limit. Suggested limits: titles 200, questions 1,000, prompt templates 8,000, objectives 1,000 characters |
| F3-S3 | must | URL fields refuse dangerous schemes | Parse `media_url` and `file_url` values: `javascript:alert(1)`, `data:text/html,…`, `vbscript:…`, `file:///etc/passwd`, `https://ok.example/v.mp4`, `evaporation.mp4` | The first four fail; https URLs and bare file names pass |
| F3-S4 | must | IDs are safe slugs | Parse `idea_id` values: `evap`, `water-cycle`, `Evap`, `a b`, `../x`, `<script>`, 101 characters long | Only lowercase letters, digits and hyphens, at most 64 characters |
| F3-S5 | should | Prompt templates use known variables only | Parse a template containing `{name}` and one containing `{password}` | The unknown variable is reported (as a warning or an error), using the list in `docs/spec` |

## Performance

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| F3-P1 | must | The sample pack parses quickly | Time 100 parses of `pack.json` in Vitest and take the median | Under 20 ms each |
| F3-P2 | must | Large packs scale | Generate a synthetic pack with 2,000 ideas, 6,000 links and 2,000 assessment rows, then parse it | Under 1 second |
| F3-P3 | should | Parsing is synchronous | Inspect the schemas | No async refinements |

## Usability (teachers see these errors through the import screen)

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| F3-U1 | must | Errors point to the exact cell | Parse a bad Ideas row (row 7 in the sheet, column `unit` = "two") | The error has the tab, sheet row number (counting the header row), column name and value |
| F3-U2 | must | Errors are in plain English with a fix | Read the messages from F3-F2, F3-S3 and F3-S4 | Each says what's wrong and what's allowed, for example: "idea_id can only use lowercase letters, numbers and hyphens (got 'Evap Two')". No raw zod codes such as `invalid_type` |
| F3-U3 | must | Every problem is reported at once | Parse a pack with 5 bad cells across 3 tabs | All 5 errors are returned together |
| F3-U4 | should | Schemas carry the spec's help text | Inspect the schema descriptions | Each field's description matches the spec's note, so the import screen can show it |

## Open question for the user (doesn't block QA)

`Ideas.explanation` is a proposed column (see `fixtures/water-cycle/README.md`). Until it's confirmed, F3 treats it as optional text, and QA checks only that it parses.
