## Found during testing

1. **Some ClassConfig and CurriculumVersion errors are raw zod messages.** Suggested weight: should.
   - **Reproduce:** run `ClassConfigSchema.safeParse({ units: [{ unit: 'x' }] })`. The message is `Invalid input: expected number, received string`, because `class-config.ts` builds `UnitOverrideSchema.unit` with bare `z.number().int().min(1).max(9999)`.
   - Running `CurriculumVersionSchema.safeParse({})` gives "Invalid input: expected string, received undefined" and `Invalid option: expected one of "draft"|"published"|"archived"`.
   - **Impact:** U2 only covers import messages, so this doesn't fail a check. But teachers will see ClassConfig errors in Teacher Settings, so the unit override should use the `integer` column builder like the other fields.
2. **XLSX percent-formatted `pass_mark` is accepted as 0.7%.** Suggested weight: should (C1 could handle this instead).
   - **Reproduce:** Excel stores a cell showing `70%` as the number 0.7. `parseTabRow('Course', {subject:'S', topic:'T', grade:6, pass_mark:0.7})` gives `ok: true, pass_mark: 0.7`, with no warning.
   - **Impact:** a class gets a near-zero pass mark without anyone noticing.
   - **Fix:** C1 could read the cell's number format, or F3 could warn when the value is between 0 and 1.
3. **A local-time `Date` cell shifts the due date by a day east of UTC.** Suggested weight: should.
   - **Reproduce:** `normalizeCell('date', d)` uses `toISOString().slice(0,10)`. Run `TZ=Pacific/Auckland` and parse `parseTabRow('Units', {unit:1, name:'n', objective:'o', due_date: new Date(2026,9,30)})`. It gives `due_date: "2026-10-29"`.
   - **Impact:** read-excel-file returns UTC dates, so the fixture is fine. A reader that builds local-time dates (or a future connector) would shift every due date back by a day.
   - **Fix:** document that date cells must be UTC midnight, or use UTC parts consistently and test with a non-UTC TZ.
4. **Row caps don't short-circuit.** Suggested weight: should.
   - **Reproduce:** `parsePack` with 200,000 `links` rows (cap 20,000) still validates every row: 814 ms and 200,001 issues.
   - **Impact:** an oversized upload costs time and memory roughly in proportion to its size before the cap message appears.
   - **Fix:** the server body-size limit (C1/I-tasks) should bound this, or the importer should check row counts before calling `parsePack`.
5. **https URLs with embedded credentials are accepted.** Suggested weight: should.
   - **Reproduce:** `media_url: "https://user:pw@evil.example/"` passes S3's rule.
   - **Impact:** it isn't a scheme risk, but credentials in a curriculum URL would be stored and shown to students.
   - **Fix:** consider rejecting `url.username` and `url.password`.
6. **Minor (no fix needed for F3):** the slug regex accepts a trailing hyphen (`x-`) and a leading digit (`1abc`). Both are within the S4 bar. I mention them only in case the spec intends a stricter slug.
