## Found during testing

1. **0016 stops redacting a secret-named key whose value is an object (regression of merged must F6-S2). Suggested weight: must.** The new nested diff flattens down to leaves, so a key named `token` that holds an object becomes a path like `config.connector.token.value`. `app.redact_secrets` checks the whole key against `SECRET_KEY_PATTERN`, then checks only its last segment. The `^token$` alternative matches neither `config.connector.token.value` nor `value`. Before 0016, the one-level diff kept `token` as an object key, and the redaction recursed into it and redacted it.
   Reproduce: use the migrated test DB and act as the app role with `actAs`, then `UPDATE class_config SET config = '{"connector":{"kind":"drive","token":{"value":"LEAK-1"}}}'`.

   | Change | 0016 (this PR) | 0015 (`down`) |
   |---|---|---|
   | `connector.token` set to `{value}` | `after {"config.connector.token.value":"LEAK-1"}` (**leaked**) | `{"config.connector":{"kind":"drive","token":"[redacted]"}}` |
   | Top level `token: {value, type}` | `"config.token.value":"LEAK-2"` (**leaked**) | `"config.token":"[redacted]"` |
   | `connector.token.value` changed | before `"OLD-3"`, after `"LEAK-3"` (**both leaked**) | redacted |
   | `client_secret` leaf, `secrets.a` | redacted | redacted |

   Today the API can't reach this, because `ClassConfigSchema` strips unknown keys and the course fields are scalars. It is still a lost DB-level guarantee: the 0015 comment says "at any depth", and the F6-S2 example is "a connector credential". Suggested fix: in the trigger, stop descending into a key whose segment matches the pattern and record it as a redacted leaf, or have `redact_secrets` test every dot-separated segment. Then add a test for `token: {…}`.
