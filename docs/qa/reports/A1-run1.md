## Found during testing
1. **The filled system prompt bypasses the D26 backstop.** This is what fails A1-F6. Suggested weight: **must**.
   - Repro: as `teacher-a1`, `PUT /api/classes/{a1}/config` with `{"course":{"topic":"Sam Student and the water cycle"},"personas":[{"persona_id":"tutor","prompt_template":"You are {name}, tutoring Sam Student (sam.student@district-a.example.org, roster-student-a1) on {topic}."}]}`. Then, as `student-a1`, `POST /api/classes/{a1}/ai/tutor {"message":"Hi"}`.
   - The provider receives and the row stores the name, email and roster ID verbatim.
   - The same path applies to pack Personas-tab overrides, curriculum defaults and course topic or subject.
   - Suggested fix: run the same `backstop.blur` over `system` with the call's roster context before the provider call and before storing it, and count the hits as privacy misses. Optionally, also refuse roster identifiers when the config is saved.
2. **The roster backstop has gaps for names outside the class, and for first names written in lowercase.** Suggested weight: **should**, or to the A7 criteria.
   - In one message, `Ada Admin` (an org admin outside the class) reached the provider and the row unblurred.
   - `sam said hi` passes through, because a single name part is matched only when capitalised. That is the documented design, but children often write names in lowercase.
   - `Sky Student` (a student in another class) was blurred only by coincidence: the shared surname part "Student" belongs to Sam Student, so it became `Sky Person B`. That also shows the over-blurring trade-off.
   - D26 names A7 as the fuller detector, so this isn't held against A1.
3. **Refused or failed calls use up rate-limit quota.** Suggested weight: **should**.
   - `limiter.take()` runs before the persona-audience 403 and the no-curriculum 409.
   - Repro: retarget `tutor` to `Teachers` in class config, call it as a student N times, and the student's own quota is spent on 403s.
   - Provider failures also count. That is reasonable, but it isn't documented.
4. **Rate limits are in memory per API process.** Suggested weight: **should** (follow-up). With N API replicas the effective limit is N× the configured value. The README says so, but §9 doesn't settle whether per-class limits must hold across replicas. The coordinator should decide before horizontal scaling.
5. **Minor:** the reply returned to the client is the model's raw text, while the stored reply is blurred. That matches D26, where the device fills labels back in, but it means a model echo of a roster identifier is shown to the student. Suggested weight: **should** (note for A7).
