## Found during testing

1. **During the F5 replay of kept edits, no save status is visible** (suggested weight: should, for whichever task adds the first autosaving control, or an F5/T follow-up). `App` awaits `client.replayPendingWrites()` before it renders the shell (`App.tsx`, `setView({ kind: 'signed-in', … })` comes after the await). That makes the only real save path in the app today invisible while it is pending. To reproduce: as `teacher-a1`, put a valid kept write in `sessionStorage['ideamap.pendingWrites']`, hold the PUT with `page.route`, then reload. For as long as the response is held, the page shows only the loading heading "Idea Map · Teacher" with 0 `role=status` nodes (`shots/replay-held.png`). There is no timeout, so a hung PUT leaves the teacher on that screen indefinitely. "Saved" is never shown early, so T1-F4's bar still holds. Suggestion: render the shell first, then replay, so "Saving…" shows during the replay.
