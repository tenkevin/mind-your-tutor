## Found during testing

Also caught by lint: `globalThis[k]` with a computed key and `global['Date']` (the `globalThis` and `global` bans), `Reflect.apply(Date.now, …)`, `Reflect.get(Math, 'random')` and `Reflect.getPrototypeOf(…)` (the `Reflect` ban), and an `export *` chain `index → ./qa-a.js → ./qa-b.js` that re-exports `node:fs` (error in `qa-b.ts`). For the runtime ones, "guard passes" means `runtime-guard.test.ts` reported "Tests 41 passed (41)" with the probe export added to `SAMPLES`, and typecheck exit 0.

1. **A local `declare const` hides any banned global from lint, and the guard doesn't cover `process`.** `no-restricted-globals` only flags references that resolve to the global scope, so a TypeScript ambient declaration in the module turns them into "locals", while at runtime they are still the real globals. 0 lint messages for each of: `declare const performance: …; performance.now()`, `declare const process: …; process.env.TZ`, `declare const fetch …`, `declare const setTimeout …`, `declare const crypto …`, `declare const Reflect …`. (Only `globalThis` is caught, by `no-shadow-restricted-names`.) End to end: `declare const process: { getBuiltinModule(m: string): … }; export const probe = () => process.getBuiltinModule('node:fs').readFileSync('/proc/uptime', 'utf8').split(' ')[0];` → lint exit 0, typecheck exit 0, guard passes, and the function returns `"362.93"` then `"363.02"` (file I/O, changes over time). `fetch`, `performance`, `crypto` and timers would still throw under the guard; `process.env`, `process.getBuiltinModule` and everything reachable from it would not. Suggested fix: ban `declare` in tracker source (`no-restricted-syntax` on `[declare=true]`), or turn on `no-shadow` with `builtinGlobals: true` for tracker files; and in the guard, replace `process` the way other globals are replaced (or at least `getBuiltinModule`, `env`, `binding`). Suggested weight: **must** (a follow-up task). It's a one-line way round both layers.
2. **A computed `.constructor` key gets past lint.** `const c = 'constr' + 'uctor'; (… as Record<string, F>)[c]('return Date.now()')` and `(new Date(0) as …)[c].now()` give 0 messages, because `no-restricted-properties` only matches static names, and the computed-access rule only covers `Date` and `Math` (`eslint.config.js:183-187`). Lint isn't a gap by itself here: the guard catches the plain call. But the Function constructor reached this way is what the runtime escapes in #3 use. Suggested fix: ban computed member access with a non-literal key throughout tracker code, or every `'constructor'` string literal. Suggested weight: **should**.
3. **Three ways round the runtime guard, all with lint exit 0, typecheck exit 0 and the guard passing:**
   - *Fresh realm:* `Fn("return process.getBuiltinModule('node:vm').runInNewContext('Math.floor(Date.now() / 1e6)')")()` (Fn from #2) returns `1792713`, from an unguarded `Date` in a new context. The README's claim that the guard catches `Date` "however `Date` is reached" isn't true. With the raw `Date.now()` the test failed only because the two calls differed by 1 ms (`expected 1792713891108 to deeply equal 1792713891107`). That's luck, not the guard working.
   - *Spoofed runner stack:* `fromRunner()` (`runtime-guard.test.ts:55-59`) trusts `new Error().stack`, and tracker code can set `Error.prepareStackTrace = () => 'a\nb\nc\n/node_modules/vitest/x.js'` (`Error` isn't banned) and then call `(new Date(0) as …)[c].now()`. The guard passes the call to the real `Date.now` and the probe returned `1792713900188`.
   - *Deferred work:* an export that returns `Promise.resolve()` chained through `.then` 10 times, then reads `Date.now()` through the computed constructor, gets the real clock after `guarded()` has restored everything (returned `1792713904742`). The guard doesn't await returned values, and `toEqual` treats any two Promises as equal.
   Suggested fix: guard `process.getBuiltinModule`/`vm`. Capture the stack with saved originals, and lock `Error.prepareStackTrace` (non-writable) while the guard is on. Await thenables returned by exports inside `guarded()`, then compare their resolved values. Suggested weight: **should** (each also needs #2 or #1 to get past lint).

Suggested fix: lint `new Date(a, b, …)` with more than one argument and the local setters; in the guard, throw on those and run the guard test under a non-UTC `TZ` (for example `process.env.TZ` set in the tracker's vitest config).
