## Found during testing

1. **Adjacent `_xHHHH_` look-alikes are altered silently in XLSX.** Suggested weight: **should** (low likelihood; same class as E2, a one-line fix).
   - Repro: a valid pack with `ideas[0].notes = 'lit _x0007_ and _x005F_x0041_ end'`, then `xlsxExport.write(packReport(pack))`, then `importPack`. The result is `ok` with notes = `'lit _x0007_ and _x005FA end'`. No refusal or diagnostic is raised.
   - LibreOffice shows the same altered text (`…-Ideas.csv`: `lit _x0007_ and _x005FA end`), so this is how spreadsheets read the file, not a quirk of C1's reader. The CSV round trip is exact.
   - Cause: `encodeXstring` (`export.ts:162`) uses `/_(x[0-9A-Fa-f]{4}_)/g`. The match consumes the trailing `_` that a following escape needs, so `_x0041_x0042_` encodes to `_x005F_x0041_x0042_`, which decodes to `_x0041B`.
   - Suggested fix: use a lookahead, `.replace(/_(?=x[0-9A-Fa-f]{4}_)/g, '_x005F_')`, plus a round-trip test on `_x0041_x0042_`.
   - Real curriculum text is unlikely to contain this, so it does not reopen E2's listed repros, but it is the same kind of silent change E2 asked to remove.
