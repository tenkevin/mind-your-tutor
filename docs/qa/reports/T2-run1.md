2. **The source card after a failed import mixes the failed file with the earlier version** (should, usability). After the failed `no-title.zip` import, the card reads "no-title.zip · CSV files · imported Oct 24, 5:24 AM" and lists the tab chips of the earlier version 7 (Ideas 2,000, Links 1,999), which read as if that file was imported. The failure panel below does say "Import failed: no draft was made … Version 7, from an earlier import, is unchanged." Suggest "upload failed" (not "imported") in the meta line for a failed job, and labelling or hiding the earlier version's chips. Repro: import a good pack, then a zip with `Ideas.title` removed (`ui-fail-column.png`).
3. **Brief stale data checks when a job succeeds** (should). In `store.ts` `follow()`, the store sets the succeeded job and only then calls `load()`. For one `/latest` round trip the view shows the new job's source card with the *previous* version's publish state and data checks (`!busy(job)` is now true while `version` is still the old one). With the 300-issue pack, the "300 errors" heading was already in the DOM before the new `/latest` arrived. Suggest keeping the checks hidden until the reload lands.
4. **Route prefix consistency after the C5 merge** (raise with the author or coordinator during the conflict fix). T2 moves C4's routes under `/api`, which the teacher app's proxy needs. C5's publish routes (`/versions/:id/diff|preview|publish`, `/classes/:id/pin`) are still unprefixed on `idea-map`, so the apps' `/api` proxy can't reach them as-is. The author resolving the conflict should decide whether they follow, likely as T8's or C5's concern rather than T2's.
