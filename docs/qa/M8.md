# QA criteria: M8 · Tracker rules v2: exercise levels, trace-back and diagnostics

Done when: per D38, D41 and §8, `rulesVersion` 2 adds exercise levels (Not started, Attempted, Familiar, Proficient), the two-layer trace-back, the baseline breakdown and the engagement indices, as pure deterministic replay of events with property tests. It applies no psychological labels, and time-to-answer is kept to the whole second (D19).
Sources: `docs/ARCHITECTURE.md` D6 (deterministic tracker), D19 and §8.2 (the event catalogue; **§12 q27 interim: Practice uses the quiz events with question ids `practice/<exercise_id>`**), D20, D21, D24, D38, D40, D41, §8.1, §8.3; `docs/decisions/2026-10-29-prototype-spec.md`; `project/Kinematics Explorer.dc.html` (level rule after a run) and `project/kinematics-graph.js` (`weakestRoot`); M1 (catalogue), M3 (rulesVersion 1), C10 (Practice tab), C12 (layers and the trace-target function in `packages/domain`).

Boundary:
- In scope: `packages/tracker` rules and their tests, plus the one adapter that reads Practice answers from quiz events (§12 q27).
- Out of scope: teacher views and their disclaimers (M9), the student UI (S6), new event types (D19 is a user decision), and anything shown to students other than their own exercise levels.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| M8-F1 | must | rulesVersion 2 beside 1 | Replay the same events under rulesVersion 1 and 2 | Version 1 outputs are unchanged, byte for byte. Version 2 adds the new outputs. Replaying stored history under version 2 needs no migration of events (§8.3) |
| M8-F2 | must | Level after one run (prototype) | Replay Practice runs of an exercise with n problems scoring n, n−1 and n−2 correct | Proficient, Familiar and Attempted respectively. An exercise with no finished run is Not started |
| M8-F3 | must | Best level kept | Replay Proficient, then a later Attempted run | The level stays Proficient (the best run counts, as in the prototype) |
| M8-F4 | must | Quiz exercises | Replay a `kind` quiz exercise whose problems come from `quiz_from` exercises, with some right | Each exercise behind a correct quiz problem rises to at least Familiar, never lowered, as in the prototype |
| M8-F5 | must | Practice is told apart (§12 q27) | Replay a mix of C3 map-quiz events and Practice events | Only `practice/<exercise_id>` answers feed exercise levels. Map-quiz mastery and XP (rulesVersion 1) are unaffected by how Practice is mapped, unless §8.3 is changed. The mapping is read through one adapter |
| M8-F6 | must | Procedural trace-back (D41) | Kinematics fixture or a DAG test pack: finish a run below Proficient on an idea with unmastered prerequisites | Walking `requires` from the idea, each step takes the unmastered prerequisite with the lowest standing (mastered first, then exercise level), ties broken by sheet order, until none is left or a cycle would repeat. The trace names the final root, the path, the exercise and the score, as `weakestRoot` does in the prototype. No trace when no prerequisite is unmastered |
| M8-F7 | must | Two-layer trace-back (D41, C12) | Water cycle: fail on a process idea whose mechanism prerequisites are unmastered | The trace goes down to the mechanism layer (C12's trace-target function), never around the process loop |
| M8-F8 | must | Knowledge gap (D38 1) | A failed target idea, then a stall or failure on its traced prerequisite | A knowledge-gap signal naming both ideas and the contributing events. Not raised from the first failure alone |
| M8-F9 | must | Baseline breakdown (D38 2) | Construct a student baseline of single-step accuracy and latency, then a deviating failure on a single-step item after prerequisites passed | A baseline-breakdown signal with its reason and evidence. The rolling baseline and the "abnormal deviation" threshold are named constants in the README. Inputs the catalogue doesn't hold (for example "after the AI supplied the missing context") come only from recorded events such as `ai.output_shown`. If an input isn't recorded, the signal isn't raised; the rules never guess |
| M8-F10 | must | Engagement indices (D38 3) | Replay longitudinal histories | Active Choice, Persistence and Mental Effort are computed only from §8.2 events (for example streaks, starts before a mission's due date, `secondsToAnswer` against item reading length). A component whose input isn't in the catalogue (for example sparring-loop completion before S4 records it, or elaboration depth, which would need typed text) is reported as unavailable, not estimated. Outputs are trends over time per student, not a single score |
| M8-F11 | must | Time to the whole second (D19) | Feed fractional and rounded `secondsToAnswer` | Rules use whole seconds; nothing finer is derived from `at` timestamps |
| M8-F12 | must | Opt-out (D24) | The same events for an opted-out student | Identical levels and signals; the student stays excluded from audits and research |
| M8-F13 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build and plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |

## Security and integrity

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| M8-S1 | must | Determinism (D6) | Property tests: random valid event sequences, replayed twice and from snapshots taken at random points | Byte-identical state each time. No clock, randomness, I/O or model calls; the F1c/F1d determinism checks pass |
| M8-S2 | must | Nothing D20 forbids | Search the rules, outputs and names | No psychological labels (for example "lazy", "anxious", "unmotivated"), no predictions, no ranking or clustering of students, no single engagement score. Diagnostics carry a reason and contributing event ids |
| M8-S3 | must | Who it is for (D21, D38) | Read the output types | Knowledge gap, baseline breakdown and engagement indices are typed as teacher-only outputs, separate from the student's own state. A student's state includes their exercise levels and nothing from these diagnostics |
| M8-S4 | must | No new tracing | Diff the event catalogue | No event type or payload field is added (D19, §12 q27) |
