# QA criteria: C7 · Progress migration rules on publish

Done when: publishing carries mastery over by idea_id and archives removed ideas, covered by tests.
Sources: `docs/ARCHITECTURE.md` D6, §7 ("Progress migration on publish": migration is a tracker rule, not a data rewrite; mastery carries by idea_id; a removed idea's progress is archived, not deleted; a newly added prerequisite never takes away an unlocked idea; a unit whose ideas changed reopens its teach-back only if the teacher chooses), §8.3; C5 publish; S1 snapshots; `docs/qa/C5.md` fixtures A and B.

## Functional

| Id | Weight | Check | Steps | Pass bar |
|---|---|---|---|---|
| C7-F1 | must | Mastery carries by idea_id | A student masters 5 ideas in A; publish B (one idea renamed, same idea_id) | All 5 remain mastered, including the renamed one |
| C7-F2 | must | Removed ideas are archived | B removes a mastered idea | It leaves the active map; its progress is kept as archived and visible to the teacher, not deleted |
| C7-F3 | must | Unlocks are never taken away | B adds a prerequisite to an idea the student had unlocked | It stays unlocked |
| C7-F4 | must | Teach-back reopens only by choice | A unit's ideas change; publish with and without "reopen teach-back" | Reopened only when the teacher chose it |
| C7-F5 | must | A replay, not a rewrite | Compare `interaction_event` before and after publishing | No event is changed or deleted; the new state comes from replay under the version change (a new rulesVersion only if rules change) |
| C7-F6 | must | Rollback | Re-pin A after B | The state replays correctly for A again |
| C7-F7 | must | Everything passes | Root lint, format:check, typecheck, test with DATABASE_URL (including `function_binding.test.ts`), build, plan check, on the head merged with current `idea-map` | All exit 0; CI green on the exact head |
