Idea Map BlueprintArchitecture v0.3 · 23 Oct 2026

How Idea Map fits together

A TypeScript platform that turns a curriculum spreadsheet into a published mind map that many classes share, with server-side AI personas, built for K-12 privacy rules. The Teacher Settings page is the first surface. The full write-up is docs/ARCHITECTURE.md in the repo.

Decisions

DecisionWhat it means for the build
TypeScript throughoutOne monorepo. Data checks, link ranking, layout and prompt filling live in one pure package used by browser, API and workers.
Publish separate from syncAn import makes a draft version. Students see only published versions, and each class is pinned to one.
Shared across classesA Curriculum is shared; a Class holds the teacher's overrides, due dates and roster.
Import and export onlyConnectors are file parsers (CSV, XLSX, database dumps). Google Drive and Cloudinary plug in later behind the same interfaces.
K-12COPPA, FERPA and state law decide sign-in, AI logging, retention and which vendors can be used.
Determinism lives in the trackerThe interaction tracker is fully deterministic and replayable. Map generation and AI may vary, but whatever they show a student is stored and logged.
Independent QA first (D7)Every task has written functional, security, performance and usability criteria before anyone claims it. A separate QA agent tests each PR, and Codex reviews merged work. Errors become fix tasks.
Curriculum Pack (D8)Eight tabs: Course, Units, Ideas, Links, Categories, Assessment, Personas, Library. Each field is sheet-only, app-only, or seeded by the sheet and overridable per class.
Explanations (D9)From the sheet; if empty, Ms. Ivy drafts one, which students see only after a teacher approves it.
Design colours kept (D10)Nocturne ships unchanged. Nine named contrast pairs are accepted exceptions to AA, and everything new must pass.
Per-class library (D11)Each class sets how the AI uses each shared document (Atlas, tutor, both or off) and can upload its own lab sheets.
Gaps don't block import (D12)Empty unit objectives and assessment questions are flagged, and Atlas drafts them for approval.
One persona list (D13)Ms. Ivy, Milo and Atlas live in one registry. A pack without a Personas tab uses them, and pack and class overrides sit on top.
Publish audience (D14)The publish preview counts students receiving this update: every unique student enrolled in the selected classes.
Explained feedback (D15)Formative feedback arrives with its reason and a Challenge this button that goes to the teacher. Summative feedback waits for the teacher. Teacher rulings become examples, never training data.
Fairness audits (D16)No demographics stored per student. Schools and districts are compared on parity, disparate impact (flag under 0.8) and teacher agreement. Feedback passes grounding, a verifier and a tone check before a student sees it.
UDL 3.0 (D17)Every student feature offers several ways to engage, read and answer, including read-aloud and spoken input, alongside WCAG 2.1 AA.
No Moodle (D18)No Moodle or LTI. The tracer borrows Moodle's design only: its event shape, educational levels and per-component privacy. Encryption uses AES-256-GCM.
What is traced (D19)Learning events only, with time on task rounded to 30 s and 5 s. Never clicks, scrolls, keystrokes, device, IP or location.
What is inferred (D20)Mastery per idea and a may need help signal for the teacher, always with its reason. No risk scores, behaviour profiles, clustering or rankings.
Who sees traces (D21)Students see their own progress, teachers their own classes, admins only school and district totals. No parent view in the app.
How long (D22)Raw events are kept while the student is enrolled, then deleted. Anonymous class totals may stay.
Race audit (D23)The district joins a pseudonymous sample with its own records and returns totals only. Idea Map never holds race.
Opt-out (D24)Tracing is on by default. A family or district can opt a student out of audits, totals and research.
Research (D25)Allowed on de-identified data under a district agreement. Identifiable or under-13 non-educational use needs parental opt-in.
Anonymous layer (D26)Names and places become labels such as Person A on the student's device before anything reaches the cloud. The server double-checks.
Specific interests (D27)Interests such as a favourite team reach the model, so examples connect to the student. Identifiers never do.
Two memories (D28)Short-term is the conversation. Long-term keeps misconceptions, what helped, pace and up to five interest categories, never feelings, family or health.
Memory controls (D29)Memory lasts while the student is enrolled. The student can see, delete or switch it off, and so can their teacher.

Import to classroom

Upload file→ Map columns→ Validate→ Derive→ Draft version→ Review checks & diff→ Publish to classes

Errors such as an unknown requires id or a prerequisite loop block publishing. Mastery carries across versions by idea_id; a newly added prerequisite never takes away an idea a student has already unlocked. Rolling back means pinning an earlier version.

Interaction tracker and map generation Spec v1

The tracker records learning events, never behaviour around them, in a log that is only ever added to. Mastery, unlocks, XP, streaks and cards are calculated from that log by fixed rules, so the same events always give the same numbers.

OutputRule
MasteredA quiz scores above the class pass mark (70 by default). Mastery % is the best score.
XP10 per correct answer, ×2 / ×3 / ×4 for runs of 2 / 4 / 6. Pass +50, perfect +50, link rebuilt +5, unit +200.
Streak+1 on the first pass of a day, in the class time zone.
May need helpThree wrong after a hint, or a prerequisite stalled for 5 school days. Teacher only, with the reason.
Student acts→ Names blurred on the device→ Tracker records the event→ Rules update progress→ Map and AI read that state→ What they show is saved and logged

Teachers see a timeline and heatmap for their own classes. Admins see school and district totals and fairness audits. Raw events are kept while the student is enrolled. Full spec: ARCHITECTURE §8.

How work moves

QA criteria written→ Agent claims and builds→ PR, CI green→ Independent QA PASS→ Up to date with idea-map→ Merged, one at a time→ Codex review

A failed QA check goes back to the agent. A Codex error on merged work becomes a fix task (<ID>cx<n>) that jumps the queue. If idea-map's CI turns red, nothing else merges until the fix lands.

AI personas

PersonaWho talks to itWhat it can see or do
Ms. Ivy · tutorStudentsCurrent idea or link, its objective, library passages
Milo · peerStudentsUnit assessment questions and key points; checks answers
Atlas · logisticsTeachersLooks up ideas, data checks, the draft diff and the library; drafts rows to export. Never edits curriculum data.

Teachers edit the templates. Fixed safety rules are added after every student-facing template, so editing a prompt can't remove them. All calls run on the server, and the model never receives student names.
